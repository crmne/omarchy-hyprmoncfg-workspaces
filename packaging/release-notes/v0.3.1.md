# hyprmoncfg Workspaces 0.3.1

Three fixes from the marketplace security review, all about input the widget reads: the daemon's socket, its replies, and the plugin list.

Install with `omarchy plugin install https://github.com/crmne/omarchy-hyprmoncfg-workspaces`.

## Fixed

- **A daemon line is capped while it arrives.** The 4 MiB limit on a status from hyprmoncfg's daemon used to apply only once the whole line had arrived, so a faulty daemon, or a program pretending to be one, could keep sending and grow the shell's memory. The widget now reads the socket as data arrives and drops the connection once an unfinished line passes 4 MiB. If a status arrives with a character split between two reads, it asks the daemon once more for a clean copy.
- **An invalid reply leads to a reconnect.** A reply with an unexpected status format stopped the six-second watchdog, so the bar could keep showing and switching by an old layout. The watchdog now runs until a valid status arrives, and reconnects otherwise.
- **Plugin probes stop at their size limit.** When the workspace planner can't open, the widget and its setup helper check which plugins are installed. Both read the whole `omarchy plugin list` output before checking its 1 MiB limit; they now stop the command as soon as it passes the limit.

## What's tested

19 model tests and 9 setup helper tests pass, including a helper test that stops an oversized plugin list. A new limits test runs the real service and probe offscreen against a fake daemon: an endless line, an invalid reply, a character split across reads, and an oversized probe. The reconnect test still passes. The runtime test, which needs a visible Hyprland session, was not run for this release, and nothing was checked live on a bar.
